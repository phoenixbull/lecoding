## Scope

A real Chromium session drove the loopback Web console against the configured
PostgreSQL Worker, Docker runtime/verification images, and third-party
OpenAI-compatible model. No provider secret, model identifier, or command output
was copied into this record.

Covered public seams:

- create a Run and restore it in bounded history;
- receive durable SSE lifecycle events through terminal status;
- approve individual model tool calls and reject/cancel a Run;
- render managed-worktree changed files and unified Diff;
- render required checks, Diff Safety, acceptance evidence, and terminal state;
- reconnect/replay without duplicate timeline entries;
- avoid requesting `/changes` before a worktree exists or after cancellation.

## Convergence found and verified

Early Runs exposed two implementation defects and one prompt-quality issue:

1. queued/preparing/cancelled views requested a missing changes resource and
   produced browser 404 noise;
2. Diff Safety ran inside the verification container, where Git metadata is
   intentionally unavailable, and returned exit 128;
3. the compatible model explored Git metadata and attempted administrator-owned
   acceptance commands unnecessarily.

The Web now loads changes only while a retained worktree can exist. The default
model instructions specify one-process argv, `/workspace`, unavailable Git
metadata, bounded exploration, and host-owned verification. Diff Safety now runs
through a host authority that revalidates the canonical managed worktree and
checks tracked plus untracked files. Terminal Run cleanup deletes both Docker
containers and anonymous dependency volumes while retaining the worktree.

Final replay Run `1ab81ea7-9a89-47ad-b5ae-d083e977c272` produced one target file,
showed its unified Diff, reached terminal SSE status, and reported:

```text
required: tests      failed (exit 1)
required: typecheck  passed
diff safety          passed (Managed worktree diff check passed)
```

After terminal delivery, `docker ps` contained only `lecoding-postgres`; no
LeCoding runtime or verification container remained. A fresh browser console
check contained no messages. The event outbox for the preceding diagnostic Run
showed every sequence acknowledged exactly once, and terminal replay displayed
both `verification_completed` and the final `status_changed` event.
